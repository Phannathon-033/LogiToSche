1.1 หลักกำรและเหตุผล 
 ปัจจุบันงานด้านโลจิสติกส์มีการใช้งานเอกสารจ านวนมากในการด าเนินงาน เช่น ใบส่งของ ใบแจ้งหนี้ ใบ
ตราส่งสินค้า ใบรายการบรรจุสินค้า และเอกสารประกอบการขนส่งประเภทต่าง ๆ ซึ่งเอกสารเหล่านี้มักมาจาก
หลายบริษัทหรือหลายหน่วยงานที่มีรูปแบบการจัดวางข้อมูลและการใช้ค าเรียกฟิลด์แตกต่างกัน ส่งผลให้การน า
ข้อมูลเข้าสู่ระบบภายในองค์กรยังต้องอาศัยการคีย์ข้อมูลด้วยมือ ท าให้ใช้เวลานาน เกิดโอกาสผิดพลาดจากมนุษย์ 
และท าให้ข้อมูลเข้าสู่ระบบล่าช้า โดยเฉพาะกรณีที่เอกสารใช้ค าเรียกแตกต่างกันแต่มีความหมายเดียวกัน เช่น 
Consignee, Receiver และ Ship To ซึ่งหมายถึงผู้รับสินค้า หรือ Truck No., Vehicle Reg. และ Plate No. ซึ่ง
หมายถึงทะเบียนรถ 
 แม้เทคโนโลยี OCR จะสามารถอ่านข้อความจากเอกสาร PDF รูปภาพ หรือเอกสารสแกนได้ แต่ OCR มี
หน้าที่หลักในการแปลงภาพเอกสารให้เป็นข้อความ และยังไม่สามารถเข้าใจความหมายของข้อมูลในเชิงบริบทได้
อย่างสมบูรณ์ ดังนั้นโครงงานนี้จึงมีแนวคิดในการพัฒนาระบบแปลงเอกสารโลจิสติกส์หลายรูปแบบเป็น JSON 
Schema โดยใช้ OCR ส าหรับอ่านข้อความจากเอกสาร และใช้ Small Language Model หรือ SLM ส าหรับ
วิเคราะห์ความหมายของข้อมูล เพื่อจับคู่ค าที่แตกต่างกันแต่มีความหมายเดียวกันให้เข้าสู่ฟิลด์มาตรฐานเดียวกัน 
พร้อมตรวจสอบความถูกต้องของข้อมูลด้วย Validation และ Confidence Score ก่อนน าข้อมูลไปใช้งานต่อใน
ระบบฐานข้อมูล ระบบ ERP ระบบ API หรือ Dashboard 
 การพัฒนาระบบดังกล่าวมีวัตถุประสงค์เพื่อช่วยลดภาระในการป้อนข้อมูลเอกสารด้วยมือ ลดระยะเวลาใน
การประมวลผลเอกสาร ลดงานคีย์ข้อมูลซ ้า ๆ และลดโอกาสเกิดข้อผิดพลาดจากการป้อนข้อมูลโดยมนุษย์ 
นอกจากนี้ การแปลงข้อมูลจากเอกสารที่มีรูปแบบแตกต่างกันให้อยู่ในรูปแบบ JSON Schema เดียวกัน จะช่วยให้
ข้อมูลสามารถน าไปจัดเก็บและเชื่อมต่อกับระบบสารสนเทศอื่นได้สะดวกมากขึ้น ส่งผลให้กระบวนการจัดการ
ข้อมูลมีความรวดเร็ว เป็นระบบ และช่วยลดทรัพยากรที่ใช้ในการด าเนินงาน 
1.2 วัตถุประสงค์ 
1. เพื่อพัฒนากระบวนการท างานร่วมกันระหว่าง OCR และ Small Language Model (SLM) 
ส าหรับการดึงข้อมูลจากเอกสารโลจิสติกส์ 
2. เพื่อพัฒนาระบบแปลงเอกสารโลจิสติกส์หลายรูปแบบให้อยู่ในรูปแบบ JSON Schema โดยใช้ 
OCR และ Small Language Model (SLM)

3. เพื่อก าหนดโครงสร้าง JSON Schema ส าหรับจัดเก็บข้อมูลจากเอกสารโลจิสติกส์ให้อยู่ใน
รูปแบบเดียวกัน 
4. เพื่อประเมินความถูกต้องของข้อมูลที่ได้จากการแปลงเอกสารด้วย OCR และ Small Language 
Model (SLM) 
1.3 ผลที่คำดว่ำจะได้รับ 
1. ได้กระบวนการท างานร่วมกันระหว่าง OCR และ Small Language Model (SLM) ที่สามารถ
น ามาใช้ในการดึงข้อมูลจากเอกสารโลจิสติกส์ได้ 
2. ได้ระบบที่สามารถแปลงเอกสารโลจิสติกส์หลายรูปแบบให้อยู่ในรูปแบบ JSON Schema โดยใช้ 
OCR และ Small Language Model (SLM) 
3. ได้โครงสร้าง JSON Schema ส าหรับจัดเก็บข้อมูลจากเอกสารโลจิสติกส์ให้อยู่ในรูปแบบเดียวกัน 
และสามารถน าไปใช้งานต่อกับระบบฐานข้อมูล ระบบ ERP ระบบ API หรือ Dashboard ได้ 
4. ได้ผลการประเมินความถูกต้องของข้อมูลที่ได้จากการแปลงเอกสาร เพื่อใช้วิเคราะห์ประสิทธิภาพ
ของระบบและเป็นแนวทางในการปรับปรุงระบบในอนาคต  
1.4 วิธีวิจัย  
1.4.1 ศึกษำและรวบรวมข้อมูล 
- ศึกษาปัญหาและความซับซ้อนของการประมวลผลเอกสารโลจิสติกส์แบบ Unstructured Data (เช่น ใบ
แจ้งหนี้, ใบตราส่งสินค้า) และผลกระทบต่อประสิทธิภาพการจัดการข้อมูลในระดับองค์กร  
- ศึกษางานวิจัยและทฤษฎีที่เกี่ยวข้องกับการประมวลผลเอกสารอัตโนมัติ ( Document AI), เทคโนโลยี 
OCR และการประยุกต์ใช้โมเดลภาษาขนาดเล็ก (SLM) 
- ศึกษาเทคโนโลยีที่เกี่ยวข้อง เช่น เครื่องมือสกัดข้อความ ( OCR Tools), กรอบการท างานของโมเดล
ภาษา, และเทคนิค Prompt Engineering เพื่อแปลงข้อมูลให้อยู่ในรูป JSON Schema 
1.4.2 วิเครำะห์และก ำหนดควำมต้องกำรของระบบ 
- วิเคราะห์ความเป็นไปได้ของโครงงานในด้านเทคนิค การเลือกโมเดลภาษาให้เหมาะสมกับทรัพยากร 
และความคุ้มค่าในการบูรณาการระบบ  
- ศึกษาความต้องการของผู้ใช้งาน เช่น ความรวดเร็วในการแปลงข้อมูล (Latency), ความถูกต้องแม่นย า 
(F1 Score), และรูปแบบ JSON Schema ที่รองรับระบบบริหารจัดการขององค์กร

- ก าหนดขอบเขตและคุณสมบัติของระบบ เช่น การรองรับไฟล์เอกสารที่หลากหลาย ( PDF, รูปภาพ) , 
ความสามารถในการจัดการข้อมูลที่มีความซับซ้อนด้วย AI, และการส่งข้อมูลไปยังฐานข้อมูลแบบเรียลไทม์ 
1.4.3 ออกแบบระบบ 
- ออกแบบโครงสร้างสถาปัตยกรรมระบบ (System Architecture) ที่เชื่อมโยงตั้งแต่ส่วนรับเข้าเอกสาร 
(Input) จนถึงการจัดเก็บผลลัพธ์ (Output) 
- ออกแบบขั้นตอนการประมวลผลข้อมูล (Pipeline Design) โดยก าหนดกลยุทธ์การเลือกเครื่องมือ OCR 
ให้เหมาะสมกับประเภทของเอกสาร 
- ออกแบบโครงสร้าง JSON Schema เพื่อเป็นมาตรฐานกลางในการแลกเปลี่ยนข้อมูล 
1.4.4 พัฒนำระบบ 
- พัฒนาไปป์ไลน์การอ่านเอกสารด้วย PaddleOCR เพื่อสกัดข้อความจากเอกสาร พร้อมข้อมูลต าแหน่ง
ของข้อความในรูปแบบ Bounding Box และค่าความมั่นใจในการตรวจจับข้อความ ( Confidence 
Score) จากนั้นน าผลลัพธ์ที่ได้มาจัดเตรียมและจัดโครงสร้างเป็นข้อมูลน าเข้าส าหรับโมเดลภาษา 
- พัฒนากลไก Prompt Engineering (APE/IPC) ร่วมกับโมเดลภาษา Qwen2.5-1.5B-Instruct โดยน า
ข้อมูลที่ได้จากกระบวนการ OCR ซึ่งประกอบด้วยข้อความ (Text) และข้อมูลที่เกี่ยวข้องกับการตรวจจับ
ข้อความ มาใช้เป็น Input ของโมเดล เพื่อวิเคราะห์ความหมายและจับคู่ข้อมูลที่มีความหมายเดียวกันแต่
ใช้ค าเรียกแตกต่างกันเข้าสู่ฟิลด์มาตรฐานที่ก าหนด จากนั้นสกัดข้อมูลให้อยู่ในรูปแบบ JSON ตาม
โครงสร้าง JSON Schema ที่ก าหนด 
- พัฒนากระบวนการตรวจสอบข้อมูล (Validation) เพื่อตรวจสอบความถูกต้องของโครงสร้าง JSON และ
ความครบถ้วนของข้อมูลตาม JSON Schema ก่อนน าข้อมูลไปจัดเก็บ 
- พัฒนาระบบฐานข้อมูลบนคลาวด์ด้วย Firebase Cloud Firestore เพื่อจัดเก็บข้อมูลที่ผ่านกระบวนการ
สกัดและตรวจสอบแล้ว โดยจัดเก็บในรูปแบบ Document และ Collection เพื่อให้สามารถน าข้อมูลไป
ใช้งานต่อในระบบหรือเชื่อมต่อผ่าน API ได้

1.4.5 กำรทดสอบและตรวจสอบควำมถูกต้อง  
- ทดสอบประสิทธิภาพของเทคโนโลยี OCR ในการสกัดข้อความจากเอกสารที่มีรูปแบบต่างกัน 
- ทดสอบกระบวนการแปลงข้อมูลจากข้อความดิบเป็น JSON Schema ตามที่ก าหนด 
- ทดสอบความถูกต้องของโมเดลผ่านค่า Precision, Recall และ F1 Score โดยเปรียบเทียบผลลัพธ์กับ
ข้อมูลจริง (Ground Truth) 
1.4.6 กำรปรับปรุงและบ ำรุงรักษำ 
- ปรับปรุงความแม่นย าของโมเดลผ่านการเพิ่มตัวอย่างการเรียนรู้ (Few-shot) หรือการปรับแต่งค าสั่ง 
(Prompt Tuning) ตามข้อผิดพลาดที่พบ 
- ปรับปรุงระบบ Rule-based Post-processing เพื่อจัดการกับข้อมูลที่ต้องอาศัยตรรกะเฉพาะทาง 
- ปรับปรุงส่วนแสดงผลข้อมูล (Dashboard) ให้เข้าใจง่ายและตรงตามความต้องการของผู้ใช้งาน 
1.4.7 จัดท ำรูปเล่มรำยงำนวิจัยฉบับสมบูรณ์ 
- รวบรวมผลการด าเนินงานตั้งแต่ขั้นตอนการศึกษาข้อมูล การออกแบบระบบ การพัฒนาระบบ ตลอดจน
ผลการทดสอบและประเมินความถูกต้องของข้อมูล มาเรียบเรียงให้อยู่ในรูปแบบรายงานวิจัยที่สมบูรณ์  
- จัดท าเอกสารประกอบ เช่น ภาพสถาปัตยกรรมระบบ ตารางเปรียบเทียบผลการทดลอง ( Precision, 
Recall, F1-Score) และตัวอย่างผลลัพธ์ JSON Schema ที่ได้จากระบบ เพื่อประกอบการอธิบายใน
รายงาน 
1.5 ขอบเขตงำนวิจัย 
- ตรวจสอบความถูกต้องและความครบถ้วนของเนื้อหา รูปแบบการอ้างอิง ( Reference) และการจัดรูปแบบ
เอกสารให้เป็นไปตามข้อก าหนดของมหาวิทยาลัย 
- น าเสนอรายงานวิจัยฉบับสมบูรณ์ต่ออาจารย์ที่ปรึกษาโครงงานเพื่อตรวจสอบและให้ข้อเสนอแนะก่อนจัดส่งฉบับ
สมบูรณ์

2.1  ทฤษฎีที่เกี่ยวข้อง 
1) ทฤษฎีและขั้นตอนการประมวลผลของเทคโนโลยีการอ่านอักขระด้วยแสง ( Optical Character 
Recognition: OCR) เทคโนโลยี OCR คือกระบวนการทางคอมพิวเตอร์ในการเปลี่ยนข้อความที่อยู่ในรูปแบบ
ภาพถ่ายหรือเอกสารสแกนให้เป็นข้อความดิจิทัล ในเชิงลึก กระบวนการท างานของ OCR ระดับองค์กร (เช่น 
Amazon Textract หรือ PaddleOCR) ประกอบด้วย 4 ขั้นตอนหลัก ได้แก่

ที่สุด และแทบไม่พบค าตอบผิดในช่วงค่าความเชื่อมั่นสูง สะท้อนให้เห็นว่าการออกแบบ Prompt ร่วมกับการ

มีนัยส าคัญ ทั้งนี้ งานวิจัยยังรายงานว่าข้อผิดพลาดที่เหลืออยู่ส่วนใหญ่เกิดจากการตีความรูปแบบวันที่ การค านวณ

2.3 เทคโนโลยีที่เกี่ยวข้อง 
2.3.1 ระบบอ่ำนอักขระด้วยแสง (Optical Character Recognition: OCR) 
 ระบบอ่านอักขระด้วยแสง (Optical Character Recognition: OCR) เป็นเทคโนโลยีที่ใช้แปลงข้อมูลจาก
เอกสารในรูปแบบภาพหรือไฟล์ PDF ให้เป็นข้อความดิจิทัลที่สามารถน าไปประมวลผล แก้ไข และค้นหาได้โดย
อัตโนมัติ เทคโนโลยีดังกล่าวช่วยลดภาระการบันทึกข้อมูลด้วยมือและเพิ่มประสิทธิภาพในการจัดการเอกสารใน
องค์กร ปัจจุบันเทคโนโลยี OCR สามารถท างานร่วมกับกระบวนการวิเคราะห์เอกสารที่ซับซ้อนได้ เช่น การ
ตรวจจับข้อความ ( Text Detection) การรู้จ าข้อความ (Text Recognition) การวิเคราะห์โครงสร้างเอกสาร 
(Layout Analysis) และการวิเคราะห์โครงสร้างตาราง ( Table Structure Recognition) โดยในโครงงานนี้
เลือกใช้ PaddleOCR เป็นเครื่องมือส าหรับตรวจจับและอ่านข้อความจากเอกสาร พร้อมระบุข้อมูลต าแหน่งของ
ข้อความในรูปแบบ Bounding Box และค่าความมั่นใจในการรู้จ าข้อความ (Confidence Score) เพื่อเตรียม
ข้อมูลส าหรับกระบวนการประมวลผลในขั้นตอนถัดไป 
 ในงานวิจัยของ Chen et al. (2025) ระบบ OCR ท าหน้าที่อ่านข้อความและโครงสร้างของเอกสาร ก่อน
ส่งข้อมูลเข้าสู่ขั้นตอนการสกัดข้อมูลส าคัญ ( Key Information Extraction: KIE) โดยใช้ Large Language 
Model (LLM) ที่ท างานร่วมกับ Configuration Table ซึ่งก าหนด Field Schema ชนิดข้อมูล (Data Type) และ
ล าดับของข้อมูล (Field Sequence) ที่ต้องการสกัดอย่างชัดเจน เพื่อให้โมเดลดึงเฉพาะข้อมูลที่ก าหนดไว้และ
จัดเก็บผลลัพธ์ในรูปแบบ JSON หากไม่พบข้อมูลในฟิลด์ที่ก าหนด ระบบจะก าหนดค่าเป็น NULL เพื่อให้โครงสร้าง
ข้อมูลมีความสอดคล้องและสามารถน าไปประมวลผลต่อได้ 
 ในการประเมินประสิทธิภาพของระบบ ผู้วิจัยได้ก าหนดฟิลด์ข้อมูลส าคัญจ านวน 13 ฟิลด์ ได้แก่ Ocean 
Vessel Name, Port of Loading, Invoice Date, Shipped on Board Date, Quantity, Invoice No, Total 
Amount, Carrier Company, Bill of Lading No, Total Containers No, 20ft Containers No, 40ft 
Containers No และ Packing เพื่อน ามาใช้ประเมินความถูกต้องของการสกัดข้อมูลด้วยค่า Precision, Recall 
และ F1-score ซึ่งสะท้อนให้เห็นว่าการก าหนดโครงสร้างข้อมูลที่ชัดเจนร่วมกับการออกแบบ Prompt มีส่วนช่วย
เพิ่มประสิทธิภาพของการสกัดข้อมูลจากเอกสาร 
 ส าหรับโครงงานนี้ PaddleOCR ท าหน้าที่เป็นขั้นตอนแรกของกระบวนการประมวลผลเอกสาร โดย
ตรวจจับและอ่านข้อความจากเอกสารโลจิสติกส์ พร้อมส่งผลลัพธ์ที่ได้เข้าสู่ขั้นตอนการเตรียมข้อมูลและ
ประมวลผลด้วย Small Language Model (SLM) เพื่อวิเคราะห์ความหมายของข้อมูลและจับคู่ข้อมูลที่มี

ความหมายเดียวกันแต่ใช้ค าเรียกแตกต่างกันเข้าสู่ฟิลด์มาตรฐานที่ก าหนด จากนั้นระบบจะสร้างผลลัพธ์ในรูปแบบ 
JSON ตามโครงสร้าง JSON Schema และตรวจสอบความถูกต้องของข้อมูลก่อนน าไปจัดเก็บหรือใช้งานใน

 2.3.2 ระบบอ่ำนอักขระด้วยแสง PaddleOCR 
 PaddleOCR เป็นชุดเครื่องมือ OCR แบบโอเพนซอร์สที่พัฒนาโดย Baidu บนเฟรมเวิร์ก Deep Learning 
PaddlePaddle ซึ่งสามารถใช้ส าหรับการตรวจจับและรู้จ าข้อความจากเอกสารและรูปภาพ โดยกระบวนการ 
OCR สามารถให้ผลลัพธ์เป็นข้อความที่ตรวจจับได้ พร้อมข้อมูลต าแหน่งของข้อความในรูปแบบ Bounding Box 
และค่าความมั่นใจในการรู้จ าข้อความ (Confidence Score) ซึ่งสามารถน าไปใช้เป็นข้อมูลส าหรับกระบวนการ
ประมวลผลเอกสารในขั้นตอนถัดไปได้ 
 ในโครงงานนี้เลือกใช้ PaddleOCR เป็นเครื่องมือหลักส าหรับการอ่านข้อความจากเอกสารโลจิสติกส์ เช่น 
ใบแจ้งหนี้ ใบตราส่งสินค้า และใบรายการบรรจุสินค้า เนื่องจากเป็นซอฟต์แวร์โอเพนซอร์สที่สามารถน ามาใช้งาน
ได้โดยไม่มีค่าใช้จ่ายด้านลิขสิทธิ์ และสามารถประยุกต์ใช้กับเอกสารที่มีรูปแบบและต าแหน่งข้อมูลแตกต่างกันได้ 
โดยผลลัพธ์จาก PaddleOCR จะถูกน าไปผ่านกระบวนการเตรียมข้อมูลก่อนเข้าสู่ขั้นตอนการประมวลผลด้วย 
Small Language Model (SLM) เพื่อวิเคราะห์ความหมายและจับคู่ข้อมูลเข้าสู่ฟิลด์มาตรฐานตาม JSON 
Schema ที่ก าหนด 
 2.3.3 โมเดลภำษำขนำดเล็ก (Small Language Models: SLM) 
 โมเดลภาษาขนาดเล็ก ( Small Language Models: SLM) เป็นโมเดลปัญญาประดิษฐ์ที่ได้รับการ
ออกแบบให้มีจ านวนพารามิเตอร์น้อยกว่าโมเดลภาษาขนาดใหญ่ (Large Language Models: LLMs) ส่งผลให้ใช้
ทรัพยากรในการประมวลผลและหน่วยความจ าน้อยกว่า และสามารถน าไปประยุกต์ใช้กับงานประมวลผล
ภาษาธรรมชาติ เช่น การสรุปข้อความ การตอบค าถาม การจ าแนกประเภทข้อมูล และการสกัดข้อมูลจากเอกสาร
ได้ ในโครงงานนี้ SLM ถูกน ามาใช้ในการวิเคราะห์และท าความเข้าใจข้อความที่ได้จากกระบวนการ OCR เพื่อสกัด
ข้อมูลและจับคู่ข้อมูลที่มีความหมายเดียวกันแต่ใช้ค าเรียกแตกต่างกันเข้าสู่ฟิลด์มาตรฐานที่ก าหนด จากนั้นสร้าง
ผลลัพธ์ในรูปแบบ JSON ตามโครงสร้าง JSON Schema และน าไปตรวจสอบความถูกต้องก่อนจัดเก็บใน
ฐานข้อมูล

 2.3.4 ฐำนข้อมูล Cloud Firestore 
 Cloud Firestore เป็นระบบฐานข้อมูลแบบ NoSQL บนแพลตฟอร์ม Firebase ของ Google ที่ออกแบบ
มาเพื่อจัดเก็บข้อมูลในรูปแบบเอกสาร ( Document) และคอลเลกชัน ( Collection) โดยใช้โครงสร้างข้อมูล
ลักษณะ JSON ท าให้มีความยืดหยุ่นในการจัดเก็บข้อมูลที่มีโครงสร้างแตกต่างกัน สามารถขยายระบบได้ง่าย และ
รองรับการเข้าถึงข้อมูลแบบเรียลไทม์จากหลายอุปกรณ์ 
 ในงานวิจัยนี้ Cloud Firestore ถูกน ามาใช้เป็นฐานข้อมูลส าหรับจัดเก็บผลลัพธ์ที่ได้จากการประมวลผล
เอกสาร ซึ่งอยู่ในรูปแบบ  JSON Schema โดยข้อมูลที่จัดเก็บประกอบด้วยข้อมูลส าคัญที่สกัดจากเอกสารโลจิ
สติกส์ เช่น หมายเลขเอกสาร วันที่ ผู้ส่ง ผู้รับ รายละเอียดสินค้า และข้อมูลอื่น ๆ ตามโครงสร้างที่ก าหนด เพื่อให้
สามารถค้นหา แก้ไข และน าข้อมูลไปใช้งานต่อในระบบสารสนเทศได้อย่างมีประสิทธิภาพ 
 2.3.5 บริกำรประมวลผลคลำวด์ส ำหรับกำรรันโมเดล (Google Colaboratory) 
 Google Colaboratory (Google Colab) เป็นบริการประมวลผลบนคลาวด์ของ Google ที่ให้ผู้ใช้
สามารถพัฒนาและรันโค้ดภาษา Python ผ่านเว็บเบราว์เซอร์ได้ โดยรองรับการใช้งานหน่วยประมวลผลกราฟิก 
(GPU) และหน่วยประมวลผลเทนเซอร์ (TPU) โดยไม่จ าเป็นต้องติดตั้งซอฟต์แวร์หรือมีฮาร์ดแวร์ประสิทธิภาพสูง
บนเครื่องคอมพิวเตอร์ส่วนบุคคล การประมวลผลโมเดลภาษาขนาดเล็ก (Small Language Models: SLM) ยังคง
ต้องใช้ทรัพยากรด้าน GPU และหน่วยความจ าในระดับหนึ่ง โดยเฉพาะในขั้นตอนการอนุมานผล ( Inference) 
ดังนั้น Google Colab จึงช่วยลดข้อจ ากัดด้านฮาร์ดแวร์และเพิ่มความสะดวกในการพัฒนาและทดลองโมเดล ใน
งานวิจัยนี้ Google Colab ถูกใช้เป็นสภาพแวดล้อมหลักส าหรับการโหลดและรันโมเดล  Qwen2.5 เพื่อ
ประมวลผลข้อความที่ได้จากระบบ OCR และแปลงข้อมูลให้อยู่ในรูปแบบ  JSON Schema ตามโครงสร้างที่
ก าหนด 
 2.3.6 กำรก ำหนดโครงสร้ำงข้อมูลด้วย JSON Schema 
 JSON Schema เป็นเทคโนโลยีที่ใช้ส าหรับก าหนดโครงสร้างของข้อมูล โดยสามารถระบุชื่อฟิลด์ ชนิด
ข้อมูล รูปแบบของค่า และข้อก าหนดของแต่ละฟิลด์ได้ การก าหนดโครงสร้างข้อมูลล่วงหน้าช่วยให้ข้อมูลที่ได้จาก
เอกสารหลายบริษัทและหลายรูปแบบสามารถจัดเก็บให้อยู่ในรูปแบบเดียวกัน รวมทั้งช่วยให้ ระบบสามารถ
ตรวจสอบความครบถ้วนและความถูกต้องของข้อมูลก่อนน าไปจัดเก็บในฐานข้อมูลหรือน าไปใช้งานกับระบบอื่น ใน
การก าหนดฟิลด์ข้อมูลส าคัญของโครงงาน ผู้วิจัยอ้างอิงจากงานวิจัยของ Chen และคณะ ซึ่งทดลองสกัดข้อมูลจาก
ใบแจ้งหนี้และใบตราส่งสินค้าของบริษัทขนส่งไต้หวัน โดยก าหนดข้อมูลเป้าหมายจ านวน 13 ฟิลด์ และน าผลการ

ข้อมูลที่ตรวจพบเข้าสู่ฟิลด์ที่ก าหนดไว้ เพื่อให้การจัดเก็บข้อมูลจากเอกสารหลายรูปแบบเป็นไปในทิศทางเดียวกัน

 ในงานวิจัยนี้เลือกใช้ JSON Schema เป็นโครงสร้างมาตรฐานส าหรับข้อมูลที่สกัดจากเอกสาร เนื่องจาก
ระบบมีความต้องการก าหนดโครงสร้างข้อมูลที่ชัดเจนและเป็นมาตรฐาน โดย JSON Schema สามารถก าหนดชื่อ
ฟิลด์ ชนิดข้อมูล รูปแบบข้อมูล และข้อก าหนดของแต่ละฟิลด์ เพื่อใช้ตรวจสอบความถูกต้องและความครบถ้วน

3.1 Graphical Abstract ของระบบ 
ระบบเริ่มต้นการท างานเมื่อผู้ใช้อัปโหลดเอกสารโลจิสติกส์เข้าสู่ระบบในรูปแบบไฟล์ PDF, JPG หรือ PNG 
จากนั้นระบบจะประมวลผลอ่านข้อความด้วยเทคนิค OCR (PaddleOCR) เพื่อตรวจจับต าแหน่งพิกัดข้อความ 
(Bounding Box) พร้อมค านวณค่าความเชื่อมั่น (Confidence Score) ของข้อความที่ตรวจพบ 
ข้อความที่ได้จากกระบวนการ OCR จะถูกส่งต่อไปยังแบบจ าลองภาษาขนาดเล็ก ( SLM) ที่ก าหนด
ชุดค าสั่งควบคุม (Prompt Configuration) เพื่อวิเคราะห์เชิงความหมายและสกัดข้อมูลเข้าสู่ฟิลด์มาตรฐาน 7 
ฟิลด์หลักตามโครงสร้าง JSON Schema ที่ก าหนดไว้ จากนั้นระบบจะแสดงผลลัพธ์ผ่านหน้าจอให้ผู้ใช้ตรวจสอบ
ความถูกต้อง (Human-in-the-Loop) ทั้งต าแหน่งพิกัดข้อความ ค่าความเชื่อมั่น และข้อมูลที่สกัดได้ โดยผู้ใช้
สามารถแก้ไขข้อมูลได้ด้วยตนเองก่อนกดยืนยัน 
เมื่อผู้ใช้ยืนยันข้อมูลแล้ว ระบบฝั่ง Backend จะด าเนินการตรวจสอบความถูกต้องของข้อมูล  ตาม
โครงสร้าง JSON Schema โดยอัตโนมัติ และบันทึกข้อมูลลงฐานข้อมูล ซึ่งผู้ใช้สามารถดาวน์โหลดและส่งออก
ผลลัพธ์สุดท้ายเป็นไฟล์ JSON Schema ไปใช้งานต่อได้ทันที ในขณะเดียวกัน ผู้ดูแลระบบ ( Admin) สามารถ
เรียกดูสถิติและประวัติการประมวลผลของเอกสารทั้งหมด รวมถึงตรวจสอบและแก้ไขข้อมูลย้อนหลังผ่าน 
Dashboard ได้อย่างเป็นอิสระ ดังรูปที่ 6

3.2.3 ระบบสำมำรถแปลงไฟล์เป็นข้อควำมจำกเอกสำรได้ 
3.2.3.1 ระบบสามารถอ่านข้อความจากเอกสารด้วย PaddleOCR ได้ 
3.2.3.2 ระบบสามารถตรวจจับต าแหน่งข้อความ (Bounding Box) ได้ 
3.2.3.3 ระบบสามารถแสดงค่าความเชื่อมั่น ( Confidence Score) ของข้อความที่ตรวจจับได้ 
3.2.4 ระบบสำมำรถสกัดข้อมูลจำกเอกสำร  โดยใช้ SLM

3.2.4.2 ระบบสามารถจับคู่ค าที่มีความหมายเดียวกันเข้าสู่ฟิลด์มาตรฐานได้

ก าหนด จ านวน 7 ฟิลด์ได้
